## 1. 设计目标与原则

| 原则 | 落地方式 |
| --- | --- |
| **端侧优先** | 所有推理与算法在本机 CPU 完成；核心库不含任何网络调用 |
| **分层解耦** | 核心库 `mm_core` 不依赖 Qt，GUI / CLI 仅作为「外壳」 |
| **接口稳定** | 可变部分是「算法实现」，不变部分是「接口」——ASR、摘要、导出均以抽象接口面对上层 |
| **可测试性** | 每个算法模块可脱离音频独立测试；提供回放引擎实现确定性回归 |
| **失败可见** | 统一 `Result<T>`；错误分级（可恢复 / 致命）并附上下文 |
| **零重量依赖** | DSP、分词、TextRank 全部自研，避免第三方二进制依赖带来的分发与审计成本 |

## 4. 模块设计

### 4.1 common —— 基础层

| 组件 | 职责 | 设计要点 |
| --- | --- | --- |
| `Result<T>` | 错误传播 | 携带 `ErrorCode` + 消息 + 阶段；`Result<void>` 特化用于无返回值场景 |
| `Logger` | 分级日志 | 单例 + 互斥锁；级别 `Trace/Debug/Info/Warn/Error`；输出目标可设为控制台/文件/回调（GUI 用回调转发到界面） |
| `Json` | 序列化 | 自研 writer/parser，支持对象、数组、字符串（含 UTF-8 与转义）、数值、布尔、null；解析失败返回 `Result` |
| `StringUtils` | 文本工具 | UTF-8 安全的 `trim/split/join/replace`；CJK 判定、中文标点判定、全角半角转换 |
| `TimeUtils` | 时间格式化 | 毫秒 ↔ `HH:MM:SS` / `HH:MM:SS,mmm`（SRT 规范） |
| `Config` | 配置 | 基于 Json 的键值读写，字段带默认值；路径净化 |

**为什么自研 Json 而不引入 nlohmann/json？** 该库为单头文件且质量极高，但本项目要求「零第三方运行时依赖以便审计与分发」，且所需能力仅为对象/数组/标量，自研约 400 行可控代码即可满足（解析器采用递归下降 + 迭代容器实现以避免深递归爆栈）。

### 4.2 audio —— 音频信号层

#### 4.2.1 WAV 读写 `wav_io`

- 解析 RIFF 块链，容忍 `LIST`/`fact` 等非关键块；
- 支持 `fmt ` 块格式码：`1`（PCM）、`3`（IEEE float）、`0xFFFE`（WAVE_FORMAT_EXTENSIBLE，读 `SubFormat` GUID 前 2 字节）；
- 位深映射：8 bit（无符号，偏置 128）→ `int16`；16/24/32 bit → 归一化 float；float32/64 → 直接读取；
- 多声道：按帧求和取平均下混；
- 写入：输出 16 bit PCM 单声道 WAV（用于测试夹具与波形回放）。

#### 4.2.2 重采样 `resampler`

两级策略：

1. **抗混叠**：当目标采样率低于源采样率时，先施加截止频率为 `0.45 × 目标率` 的窗函数 FIR 低通；
2. **线性插值重采样**：以源时间轴为基准逐输出点插值。

> 选择理由：会议语音的主要能量集中在 300–3400 Hz，线性插值在高倍降采样（如 48k → 16k）配合前置抗混叠滤波后，对 ASR 前端（Mel 特征）的影响可忽略，而实现与验证成本远低于多相滤波器组。测试将验证重采样后信号在通带内幅度误差 < 3%。

#### 4.2.3 变换与特征 `fft` / `mel`

- `Fft`：迭代式基-2 Cooley-Tukey，输入零填充至 2 的幂；提供实数序列快速变换 `rfft`（返回 N/2+1 复数）；
- `MelFilterBank`：24 阶三角滤波器，覆盖 0–8 kHz（16 kHz 采样时的 Nyquist），赫兹—梅尔换算采用 HTK 公式 `m = 2595·log10(1 + f/700)`；
- `MfccExtractor`：预加重(0.97) → 分帧（25 ms / 10 ms 汉明窗）→ 幅度谱 → Mel 能量 → 对数 → DCT-II 取前 13 维 → 倒谱提升；同时可计算一阶差分。

#### 4.2.4 语音活动检测 `vad`

双门限 + 迟滞的工程化方案：

| 步骤 | 说明 |
| --- | --- |
| 分帧 | 25 ms 帧长、10 ms 帧移 |
| 能量计算 | 帧 RMS → dBFS |
| 噪声底估计 | 初始 100 帧取 10% 分位数；运行期以「静音帧的指数滑动平均」缓慢跟踪 |
| 判决 | `能量 > 噪声底 + 门限Δ` **且** `过零率 < 上限` 判定为语音候选 |
| 迟滞（hangover） | 进入语音需连续 N 帧成立（默认 3）；退出语音需连续 M 帧静音（默认 8） |
| 后处理 | 平滑、剔除短于 `minSpeechMs`（默认 200 ms）的段、合并间隔小于 `minSilenceMs`（默认 300 ms）的相邻段 |
| 长段切分 | 超过 `maxSegmentMs`（默认 30 s）时在段内最小能量帧处切分 |

门限 `Δ` 自适应：`Δ = clamp(6 dB, 0.15 × (语音能量中位数 − 噪声底), 20 dB)`，避免固定门限在低信噪比下失效。

#### 4.2.5 分段 `segmenter` 与转写单元分组 `groupSegments`

**分段**：将 VAD 输出的语音段整理为带 `padding`（默认 200 ms）的切片，避免切掉字头字尾。
注意 `slice()` 会向前扩展并裁剪边界，因此**必须使用其 `actualStartMsOut` 出参回填时间戳**，
否则会产生一个 `padMs` 的系统偏移（缺陷 D2）。

**转写单元分组**：whisper 系列模型无论输入多短都会完整编码一个 30 秒窗口，因此「每个语音段
单独调用一次识别引擎」会产生 N 次固定开销。`groupSegments()` 按「相邻 + 间隔 ≤ `mergeGapMs`
+ 合并后不超过 `maxUnitMs`」把语音段聚合为转写单元，实测吞吐提升约 3.4 倍（详见测试报告 §5.2）。

```
语音段:  [1.6-5.4] [7.0-11.6] [13.1-18.5] [20.1-25.6] [27.1-30.9] [32.5-36.6] [38.2-42.5] [44.1-48.4]
                ↓  groupSegments(maxUnitMs=25000, mergeGapMs=2500)
转写单元: [1.6 ——————— 25.6] [27.1 ————————————— 48.4]     ← 2 次推理而非 8 次
                ↓  逐单元识别后，按成员段时长权重切分文本回填
语音段文本: 每段各得一段文本，索引仍与语音段一一对应
```

分组只影响「调用识别的粒度」，**不改变**对外的时间轴与索引对齐契约。

### 4.3 asr —— 语音识别层

#### 4.3.1 抽象接口

```cpp
class IAsrEngine {
public:
    virtual ~IAsrEngine() = default;
    virtual std::string name() const = 0;
    virtual bool isModelLoaded() const = 0;
    virtual Result<void> loadModel(const AsrModelConfig& cfg) = 0;
    virtual Result<AsrSegment> transcribe(
        const AudioBuffer& chunk, int64_t chunkOffsetMs) = 0;
    virtual AsrCapabilities capabilities() const = 0;
};
```

设计要点：**逐段转写**而非整段；由 Pipeline 负责切段与时间戳偏移拼接。这样既降低单次推理的内存峰值，又天然支持「按段取消」。

#### 4.3.2 后端实现

| 实现 | 说明 | 启用条件 |
| --- | --- | --- |
| `WhisperCppEngine` | 适配 whisper.cpp：`whisper_init_from_file_with_params` → `whisper_full`，参数映射见 §4.3.3 | `MEETMIND_WITH_WHISPER=ON` 且模型文件存在 |
| `ReplayAsrEngine` | 按预设脚本 + VAD 段长回放文本，用于确定性回归测试与「无模型演示模式」 | 始终可用 |
| `NullAsrEngine` | 返回空结果，用于仅跑前端链路 | 始终可用 |

`AsrFactory` 依据 `AsrModelConfig::backend`（`"auto" | "whisper" | "replay" | "null"`）与运行环境选择实现，`auto` 的优先级为 whisper → replay。

#### 4.3.3 whisper.cpp 参数映射

| 参数 | 取值 | 理由 |
| --- | --- | --- |
| `n_threads` | `max(2, hardware_concurrency()/2)` | 保留交互余量 |
| `translate` | `false` | 只转写不翻译 |
| `language` | 由配置指定，`"auto"` → `nullptr` | 中文场景显式指定可提升稳定性 |
| `no_timestamps` | `false` | 需要 SRT 时间戳 |
| `print_progress` | `false` | 进度由 Pipeline 统一上报 |
| `temperature_inc` | `0.2` | 兜底重试策略 |

#### 4.3.4 文本后处理（顺序固定）

1. **`TraditionalConverter`（繁转简）**：whisper 对中文常在繁体/简体之间摇摆（实测 small 模型约
   一半句子输出繁体）。统一转简体是关键词抽取与纪要可读性的前置条件。
   实现为**字符级映射表**（`data/t2s_zh.txt`，4303 条，由 `tools/prepare_data.py --t2s` 从 zhconv
   生成并逐字符验证）。选择字符级而非整词替换，是为了不因分词错误而漏转。
   **必须最先执行**：后续 ITN 的数词规则基于简体字表。
2. **`TextNormalizer`（ITN）**：中文数词 → 阿拉伯数字（含「万/亿/千/百/十」进位）、
   「百分之X」→「X%」、「九月」→「9月」（仅对日期/时间量词生效，避免误伤口语）；
   对已是阿拉伯数字的内容保持幂等。
3. **`PunctuationRestorer`**：当片段末尾无终止标点时，依据「与下一段的间隔时长」与句式特征
   判定插入「，」「。」「？」；对超长无标点串按语义连接词（但是/所以/然后）再切分。
   注意：「吧」是建议语气词（「我们开始吧」），不计入疑问标记（缺陷 D6）。

### 4.4 diar —— 说话人分离层

```
段级音频 ──► MFCC(13维) ──► 统计量拼接 ──► L2 归一化 ──► 凝聚层次聚类 ──► 说话人标签
                            均值13 + 标准差13 + ΔΔ均值13 = 39 维
```

- **距离**：余弦距离 `1 − cos(θ)`；
- **聚类**：凝聚式（Agglomerative），初始每段一类，反复合并最小距离对，直到最小距离 > `mergeThreshold`（默认 0.35）或达到目标人数；
- **目标人数**：`SpeakerMode::Auto` 时用「距离跳变检测」（相邻合并距离增幅 > 1.5 倍时停止）估计；`Fixed(n)` 时聚到 n 类；
- **平滑**：对时间序列做中值滤波（窗口 3），消除单段误判；
- **短板**：基于 MFCC 统计量的嵌入在短段（< 1 s）上不稳定，故对短于 800 ms 的段按时间邻接继承前一说话人标签。

### 4.5 nlp —— 自然语言层

#### 4.5.1 分词 `tokenizer`

采用与 jieba 同源的**最大概率路径法**：

1. 依据词典构建字符 DAG：以字 `i` 为起点，枚举所有 `i..j` 在词典中的词；
2. 动态规划求最大对数概率路径：`route[i] = max_j (log(freq(word)/total) + route[j+1])`；
3. 未登录词（DAG 中无匹配的连续汉字）按「单字 + 二元组」策略回退；
4. 英文/数字/百分号/连字符组成整体词元；
5. 输出带词性的候选（词性为可选扩展，本期仅输出词元与词频）。

词典来源：`data/lexicon_zh.txt`（`词 词频 词性` 制表符分隔）。加载时构建哈希表，首次访问惰性加载并缓存。

#### 4.5.2 停用词 `stopwords`

`data/stopwords_zh.txt`，含中文虚词、代词与会议口语填充词（「那个」「就是说」「大概」）。

#### 4.5.3 TextRank `textrank`

- 图为加权无向图，节点为词元（或句子），边权重为共现次数（窗口 `W=5`，句子级为相似度）；
- 迭代公式 `WS(Vi) = (1−d) + d · Σ_j (w_ji / Σ_k w_jk) · WS(Vj)`，`d=0.85`，迭代至 `max|Δ| < 1e-4` 或 100 轮；
- 句子相似度：分词后词集的重叠度 `|S∩T| / (log|S| + log|T|)`（TextRank 原文定义）。

#### 4.5.4 关键词 `keyword_extractor`

融合排序：`score = α · norm(TextRank) + (1−α) · norm(TF-IDF)`，`α=0.6`。TF-IDF 语料统计量为基于本项目 `data/` 内置词频的近似 IDF：`idf = log(N / (1 + freq))`。

#### 4.5.5 摘要 `summarizer`

MMR（Maximal Marginal Relevance）贪心选择：

```
MMR = argmax_i [ λ·Sim(s_i, D) − (1−λ)·max_{s_j∈S} Sim(s_i, s_j) ]
```

- `Sim(s, D)` 用句子的 TextRank 值；
- 句数上限 `k = clamp(ceil(句数 × ratio), 3, 20)`，`ratio` 默认 0.25；
- `λ=0.7`；
- 输出保留原句时间戳，便于在纪要中回跳。

#### 4.5.6 待办与决议抽取 `action_item_extractor` / `decision_extractor`

规则 + 模式匹配（可解释、零训练成本，符合端侧要求）：

| 字段 | 抽取规则 |
| --- | --- |
| 是否待办 | 命中**施动/祈使类**触发词表：`待办 / 行动项 / 跟进 / 负责 / 责任人 / 请 / 需要 / 务必 / 尽快 / 落实 / 安排 / 提交 / 输出 / 整理 / 补充 / 对接 / 推动 / 修复 / 优化 / 准备 / 调研 / 确认 / 明确 / 制定 / 完成 / 推进 / 同步 / 敲定`。<br>**刻意排除名词类**（`排期 / 上线 / 评审 / 方案`）：它们在会议里几乎每句都出现，作为触发词会把大量陈述句误判为待办 |
| 责任人 | (a) 显式「@姓名」「由 X 负责」「X 来跟进」；(b) 说话人推断——若主语为「我」且句含动作，则责任人 = 当前说话人。<br>候选名过滤：向后扫描以「由/请/让/叫」为左边界；候选内部不得含边界字符；候选不得以 88 个功能字/副词开头（剔除「继续」「尽快」等动词短语） |
| 截止时间 | 规则族：`X月X日/号`、`下周X/本周X`、`X个工作日`、`月底/季度末`、`明年X月`，统一转为 ISO 日期（相对「会议日期」计算）。<br>`今天/明天` 采用**收尾语黑名单**排除（`就到这里 / 先这样 / 到此为止 / 再聊`），而非「必须有施动动词」的门槛——后者会误杀「明天给我」这类正常待办 |
| 优先级 | 含 `尽快/紧急/优先/必须` → 高；含 `可以/可选/有空` → 低；其余中 |
| 决议 | 命中 `决定 / 确定 / 通过 / 同意 / 确认 / 否决 / 驳回 / 敲定 / 达成一致` 且句子主语非疑问 |

#### 4.5.7 话题分段 `topic_segmenter`

TextTiling 简化版：

1. 以句为基本单位，构造「伪句」块（每 3 句一块）；
2. 计算相邻块的词向量余弦相似度形成相似度谷图；
3. 谷底（局部极小且低于 `mean − 0.5·std`）作为议题边界；
4. 每段取 TextRank 权重最高的关键词组合作为议题标题。

#### 4.5.8 纪要生成 `minutes_builder`

装配顺序：标题（文件名/首句/关键词）→ 概览（摘要前 2 句 + 统计）→ 议题 → 关键结论 → 决议 → 待办 → 关键词 → 风险提示（低置信段、未指明责任人的待办、超长会议）。

#### 4.5.9 摘要后端可插拔

`MinutesBuilder::build()` 接受 `ISummarizer*`。默认实现为完全离线的 `ExtractiveSummarizer`
（TextRank + MMR）；传入的后端 `available() == false` 或为空指针时自动回退抽取式，绝不产出空纪要。
自定义后端的接入点已通过 `nlp_minutes.自定义摘要后端可插拔` 用例验证真实可用。

### 4.6 pipeline —— 编排层

```
[1] 解码 WAV              → AudioBuffer + AudioQualityReport   (0–8%)
[2] 重采样至 16 kHz       → AudioBuffer                          (8–12%)
[3] VAD + 分段 + 单元分组  → vector<SpeechSegment> + 转写单元     (12–18%)
[4] 逐【单元】ASR          → 文本按段时长权重回填                  (18–70%)
[5] 说话人分离            → speakerId 回填                       (70–78%)
[6] 繁转简 → ITN → 标点    → 规范化文本                          (78–84%)
[7] 纪要生成              → Minutes + 报告定稿                   (84–96%)
[8] 导出                  → 文件                                 (96–100%)
```

> **报告定稿必须发生在导出之前**：导出产物本身要包含这份报告，若把导出耗时也计入总耗时，
> 则任何已写出的文件都无法反映真实值（鸡生蛋问题）。因此 `totalMs` 定义为「解码→纪要」的耗时，
> 导出耗时单列 `exportMs`。同理，`Exporter` 先 `planPaths()` 算出全部目标路径再渲染，
> 使产物内能准确列出「本次写出的文件」。

- **进度**：`ProgressCallback(stage, stageIndex, stageCount, fraction, message)`；
- **取消**：`CancelToken`（`std::atomic<bool>`），在每个段循环边界检查，取消时返回 `ErrorCode::Cancelled` 并清理半成品；
- **计时**：每阶段记录耗时写入 `PipelineReport`，供性能验收；
- **短路**：任一阶段的 `Result` 失败即停止，错误向上携带阶段名。

### 4.7 export —— 导出层

| 格式 | 结构要点 |
| --- | --- |
| Markdown | 标题 + 元信息表 + 概览 + 议题 + 决议（复选框）+ 待办表（责任人/截止/优先级）+ 关键词 + 全文转写（按说话人分段） |
| JSON | `{ schemaVersion, meta, quality, transcript[], speakers[], minutes, report }`，全字段可被二次开发消费 |
| SRT | 每段一条，序号 + 时间戳 + `[说话人] 文本` |
| TXT | `[HH:MM:SS] 说话人N: 文本` |
| HTML | 内联 CSS 的自包含页面，含目录锚点 |

**原子写**：先写 `<name>.tmp`，`fsync` 语义后 `std::filesystem::rename` 覆盖，避免中断产生半文件。

### 4.8 storage —— 持久化层

- `sessions/index.json`：会话列表（id、标题、时间、时长、路径、关键词 Top5）；
- `sessions/<id>.json`：完整 `PipelineResult` 快照；
- 配置：`%APPDATA%/MeetMind/config.json`（Windows）/ `~/.config/MeetMind/config.json`（其他）。

## 6. 性能设计

| 环节 | 优化手段 |
| --- | --- |
| 音频解码 | 预分配 `vector`，按块读取；避免逐样本 `push_back` |
| 重采样 | 预计算插值索引与权重，内层循环无分支 |
| FFT | 预计算旋转因子表（`twiddle`），按帧复用；Mel 滤波器组稀疏化（三角带宽内才计算） |
| ASR | 逐段推理，内存峰值与段长而非会议时长相关；线程数与 CPU 核数绑定 |
| 分词 | 词典哈希表；DAG 构建 O(n·maxWordLen)，路径 DP 单次线性 |
| TextRank | 邻接表表示；收敛早停（Δ < 1e-4） |
| 并发 | Pipeline 单线程串行（ASR 内部多线程），避免过度切换 |

## 7. 安全与隐私设计

| 风险 | 控制措施 |
| --- | --- |
| 音频外泄 | 核心与 GUI 均无网络调用（`src/` 全量检索无 socket/http/curl/WinHTTP） |
| 日志泄露内容 | 日志仅记录长度、时长、路径文件名，不记录文本正文（`Trace` 级别除外，默认关闭） |
| 路径穿越 | 导出文件名经 `sanitizeFileName`：剔除 `..`、`/`、`\`、控制字符与 Windows 保留名 |
| 半成品文件 | 临时文件 + 原子替换 |
| 恶意 JSON | 解析器限制嵌套深度（≤ 64）与字符串长度，防止资源耗尽 |
| 强制离线 | 环境变量 `MEETMIND_OFFLINE=1` 时禁止初始化任何网络后端 |
