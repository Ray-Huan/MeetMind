## 1. 项目背景与目标

### 1.1 背景

会议是团队信息交换的核心场景，但会后整理纪要长期依赖人工，存在三个痛点：

1. **耗时长**：1 小时会议通常需要 0.5–1 小时人工整理，且容易遗漏；
2. **隐私风险**：云端方案需将会议原始音频上传，涉及商业机密与合规问题；
3. **网络依赖**：弱网、内网隔离、涉密环境中云端方案不可用。

### 1.2 项目目标

构建一款**完全端侧运行、断网可用**的桌面会议纪要工具，实现：

> 输入一份会议录音（WAV）→ 输出一份结构化会议纪要（Markdown/JSON/SRT/HTML）

全流程不产生任何网络请求，音频与文本数据不离开本机。

### 1.3 范围界定

**纳入范围（In Scope）**

- 单机桌面应用（GUI + 命令行双入口）
- 离线音频文件转写（WAV 输入）
- 说话人分离（无监督聚类，不依赖声纹注册）
- 智能纪要：关键词、摘要、待办事项、决议、话题分段
- 多格式导出与会话历史管理

**排除范围（Out of Scope）**

- 实时麦克风流式转写（架构预留 `IAsrEngine` 流式接口，本期仅实现文件批处理）
- 云端同步、多端协作、账号体系
- 视频文件解码（仅接受已解码的音频容器）
- 硬件相关的驱动、采集卡、嵌入式部署（按项目约束规避硬件话题）

## 3. 功能需求

### FR-1 音频接入

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-1.1 | 支持读取 RIFF/WAVE 容器音频 | 覆盖 PCM 8/16/24/32 bit 与 IEEE float 32/64 bit 编码 |
| FR-1.2 | 支持单声道与多声道输入 | 多声道自动下混为单声道 |
| FR-1.3 | 支持任意采样率 | 统一重采样至 16 kHz（ASR 输入标准），重采样带抗混叠预处理 |
| FR-1.4 | 对损坏文件给出明确错误 | 返回错误码与可读消息，不崩溃 |
| FR-1.5 | 输出音频质量报告 | 时长、采样率、声道数、峰值电平、削波比例、RMS |

### FR-2 语音活动检测与分段

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-2.1 | 区分语音段与静音段 | 基于自适应能量门限 + 过零率双门限判决 |
| FR-2.2 | 抗噪与抗抖动 | 引入 hangover（迟滞）机制与最小语音段/最小静音段约束 |
| FR-2.3 | 长语音自动切分 | 单段超过设定上限时按最低能量点二分切分 |
| FR-2.4 | 输出时间戳 | 每段给出起止毫秒，误差 ≤ 30 ms |

### FR-3 语音转写

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-3.1 | 抽象可插拔转写后端 | 通过 `IAsrEngine` 接口接入，不修改上层即可替换引擎 |
| FR-3.2 | 端侧离线推理 | 默认后端为 whisper.cpp（GGML/CPU），全程无网络 |
| FR-3.3 | 中文识别 | 支持 `zh` / `auto` 语言设定，输出文本规范化 |
| FR-3.4 | 逆文本正则化（ITN） | 中文数字转阿拉伯数字、百分比/金额/时间单位规范化 |
| FR-3.5 | 标点恢复 | 无标点输出时按停顿与句式规则插入逗号、句号、问号 |
| FR-3.6 | 逐段置信度 | 输出每段平均对数概率供界面提示低置信片段 |
| FR-3.7 | 可复现测试 | 提供回放式引擎，支持在无模型环境下做确定性回归测试 |

### FR-4 说话人分离

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-4.1 | 无监督说话人聚类 | 无需预先注册声纹 |
| FR-4.2 | 说话人数量自适应 | 支持自动估计，也支持人工指定 1–8 人 |
| FR-4.3 | 声纹特征 | 段级 MFCC 统计量（均值/方差/一阶差分）构成固定维度嵌入 |
| FR-4.4 | 聚类算法 | 凝聚式层次聚类 + 余弦距离，输出发言轮次时间轴 |

### FR-5 智能纪要

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-5.1 | 中文分词 | 词典驱动最大概率路径（DAG + 动态规划），支持未登录词字符回退与英文/数字整体识别 |
| FR-5.2 | 关键词抽取 | TextRank 与 TF-IDF 融合排序，输出 Top-K 及权重 |
| FR-5.3 | 会议摘要 | MMR 冗余抑制的抽取式摘要，按压缩比自适应句数 |
| FR-5.4 | 待办事项抽取 | 识别任务动作、责任人、截止时间三要素，支持"待办/行动项/跟进"等触发词 |
| FR-5.5 | 决议抽取 | 识别"决定/通过/同意/确定/否决"等决策句 |
| FR-5.6 | 话题分段 | 基于相邻句词分布相似度的 TextTiling 简化算法划分议题 |
| FR-5.7 | 纪要结构生成 | 输出会议概览、议题、决议、待办、关键词、风险提示 |
| FR-5.8 | 摘要后端可插拔 | `ISummarizer` 抽象，默认纯离线抽取式，可扩展为其它摘要实现 |

### FR-6 结果导出

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-6.1 | Markdown 导出 | 结构完整，可直接渲染 |
| FR-6.2 | JSON 导出 | 全量结构化数据，含 schema 版本号 |
| FR-6.3 | SRT 导出 | 时间戳符合 `HH:MM:SS,mmm --> HH:MM:SS,mmm` 规范 |
| FR-6.4 | 纯文本导出 | 带说话人与时间戳的可读文本 |
| FR-6.5 | HTML 导出 | 自包含单文件，无外部资源依赖 |

### FR-7 交互与工程化

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-7.1 | 图形界面 | Qt Widgets：波形视图、转写表格、纪要面板、进度反馈 |
| FR-7.2 | 后台执行 | 长任务在独立线程运行，界面不冻结，支持取消 |
| FR-7.3 | 拖拽导入 | 支持拖入 WAV 文件直接处理 |

## 4. 非功能需求

### NFR-1 性能

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| 音频解码吞吐 | ≥ 50× 实时 | 16 kHz 单声道 WAV 解码 + 重采样 |
| VAD 吞吐 | ≥ 200× 实时 | 帧长 25 ms、帧移 10 ms |
| 端到端转写速度 | ≥ 1.5× 实时 | whisper.cpp base 模型、CPU、4 线程，含 VAD 与 NLP |
| 纪要生成耗时 | ≤ 500 ms | 10 000 字转写文本 |
| 内存峰值 | ≤ 1.5 GB | 含 1 小时会议音频与模型权重 |
| 界面响应 | 交互延迟 ≤ 100 ms | 全流程在后台线程执行 |

### NFR-2 可靠性

- 单文件处理失败不得导致进程崩溃或数据损坏；
- 所有外部输入（文件、配置、模型）均需校验；
- 导出采用「临时文件 + 原子替换」，避免半成品文件；
- 异常路径统一走 `Result<T>` 返回，禁止在核心库中抛出未捕获异常。

### NFR-3 安全性

- 默认零网络请求，不采集遥测；
- 不写入音频原文到日志；
- 导出文件名对路径穿越字符做净化；
- 环境变量 `MEETMIND_OFFLINE=1` 可强制关闭可选的网络型摘要后端。

### NFR-4 可维护性

- 分层架构，核心库 `mm_core` 不依赖 Qt，可独立复用；
- 单元测试覆盖核心算法模块，关键模块语句覆盖率 ≥ 70%；
- 编译开启 `-Wall -Wextra` 且零告警；
- 公开接口均带中文 Doxygen 注释。

### NFR-5 可移植性

- 核心库仅依赖 C++17 标准库与平台无关的算法实现；
- 平台相关代码（网络、进程）以 `#ifdef` 隔离。

### NFR-6 可用性

- 首次运行无模型时给出明确引导，不静默失败；
- 进度以「阶段 + 百分比」呈现，长任务可取消。

## 5. 约束与假设

| 类型 | 内容 |
| --- | --- |
| 技术约束 | 必须使用 C++17 与 Qt 6；核心算法不得依赖云端服务 |
| 输入约束 | 本期仅接收 WAV（PCM/IEEE float）；其他格式需用户自行转码 |
| 模型约束 | 语音识别模型以文件形式随程序分发，需用户显式指定路径 |
| 硬件假设 | x86-64 CPU，至少 4 GB 可用内存；GPU 加速为可选增强 |
| 数据假设 | 会议语言以中文普通话为主，混有少量英文技术词汇 |

## 6. 验收标准（Definition of Done）

1. 全部构建目标（`mm_core` / `mm_cli` / `mm_gui` / `mm_tests`）在干净的 MinGW + Qt6 环境下编译通过，`-Wall -Wextra` 零告警；
2. 单元测试与集成测试全部通过，测试报告可复现；
3. 使用真实中文会议语音完成一次端到端验证，产出纪要文件；
4. GUI 可启动并完成一次完整处理流程；
5. 需求文档、设计文档、接口文档、测试报告齐备且与代码一致；
6. `README.md` 提供从零构建与运行的完整步骤。
