## 1. 测试策略

| 层级 | 目标 | 手段 |
| --- | --- | --- |
| 单元测试 | 每个算法模块的输入输出契约 | 自研轻量断言框架（零依赖），覆盖边界与非法输入 |
| 集成测试 | 流水线各阶段协同、索引对齐、导出产物 | 合成音频 + 回放引擎，断言产物结构与内容 |
| 端到端测试 | 真实语音 → 真实识别 → 真实纪要 | Windows SAPI 合成中文会议语音 + whisper.cpp 端侧推理 |
| 界面测试 | 主窗口可渲染、不崩溃 | 离屏/本机平台渲染为 PNG 并校验尺寸与非空 |
| 性能测试 | 各阶段吞吐与整体实时倍率 | 阶段计时 + 多配置对照实验 |
| 静态检查 | 本项目源码零告警 | `-Wall -Wextra -Wpedantic`（仅施加于本项目目标） |

**为什么自研测试框架**：项目定位是「零第三方运行时依赖、可审计」。测试框架属于开发期依赖，
但引入 gtest/catch2 仍需额外拉取与维护；本框架约 200 行，提供 `EXPECT/REQUIRE` 语义、
按名称过滤、逐用例计时与失败清单，足以支撑本项目。

### 3.2 关键断言举例（可验证的"强断言"）

| 用例 | 断言内容 | 为什么这样断言 |
| --- | --- | --- |
| `audio_fft.正逆变换可还原` | `inverse(forward(x)) ≈ x`，逐点误差 < 1e-3 | 直接验证变换的正确性，而非只看"没崩" |
| `audio_fft.单音信号谱峰位置正确` | 1 kHz 正弦的谱峰落在第 64 号频点 | 频谱位置是绝对可验证的物理量 |
| `audio_resample.降采样长度与频率保持` | 48 kHz→16 kHz 后主频仍在 1 kHz ±40 Hz | 验证抗混叠 + 插值没有破坏通带 |
| `audio_wav.多声道下混为单声道` | 左右反相的立体声下混后峰值 < 0.01 | 反相是最强的下混正确性检验 |
| `nlp_tokenizer.分词保持原文可还原` | `join(cut(text))` == 去掉标点的原文 | 分词不得丢字，这是最基本的不变量 |
| `nlp_textrank.归一化处理常量序列` | 常量序列归一化后恒为 0.5，非常量序列端点恰为 0 与 1 | 该断言正是为了捕捉 D1 的别名缺陷 |
| `nlp_itn.已是数字时保持幂等` | `30%`、`2026年9月14日`、`v2.0` 转换后不变 | 幂等性是文本规范化的硬要求 |
| `nlp_action.截止时间抽取` | `下周三` → `2026-09-23`（会议日 2026-09-14 为周一） | 相对时间推算可用日历反算验证 |
| `diar_cluster.两个可分簇被正确识别` | 12 个样本 → 恰好 2 簇，且分组完全正确 | 聚类算法本身可确定性验证 |
| `pipeline.完整流程产出纪要并导出文件` | 段数/转写段/说话人标签数量一致，时间戳单调且在音频范围内，导出文件存在且非空 | 端到端一致性 |
| `pipeline.转写单元分组与索引对齐` | 分组后 `units=1`、`asr.segments.size()==segments.size()`、逐段起止时间相等 | 分组不得破坏索引对齐 |
| `nlp_minutes.自定义摘要后端可插拔` | 注入自定义 `ISummarizer` 后 `engine=stub`；后端不可用/为空时回退 `extractive` | 验证扩展点真实可用，而非只有接口 |

## 5. 性能测试

### 5.1 各阶段耗时（50.5 秒音频，whisper small，8 线程）

| 阶段 | 耗时 |
| --- | --- |
| 解码音频 | 4 ms |
| 重采样（22.05 kHz → 16 kHz） | 42 ms |
| 语音检测 | 3 ms |
| **语音转写** | **约 22 000 ms** |
| 说话人分离 | 71 ms |
| 文本规范化 | < 1 ms |
| 纪要生成 | 51 ms |
| 导出（4 种格式） | 278 ms |
| **处理总计（不含导出）** | **约 23 100 ms** |

**结论**：除转写外的全部处理（解码 + 重采样 + VAD + 说话人 + 规范化 + 纪要）合计 < 200 ms，
算法实现远高于 NFR-1「VAD ≥ 200× 实时」的要求；瓶颈完全在 ASR 模型推理上。

### 5.2 关键优化：转写单元分组（对照实验）

**问题**：最初按 VAD 语音段逐个调用识别引擎。whisper 系列模型无论输入多短都会完整编码一个
30 秒窗口，因此 1.2 秒的段与 30 秒的段耗时几乎相同 —— 8 次调用产生 8 次固定开销。

**对照实验**（同一音频、同一模型、仅改合并参数）：

| 转写单元上限 | 允许合并的最大段间隔 | 实际单元数 | 转写耗时 | 整体实时倍率 |
| --- | --- | --- | --- | --- |
| 0（逐段） | — | 8 | 82 413 ms | 0.61× |
| 25 000 ms | 1 500 ms | 8（未触发合并） | 92 125 ms | 0.55× |
| 25 000 ms | 2 500 ms | **2** | **25 412 ms** | **1.97×** |
| 25 000 ms | 5 000 ms | 2 | 25 776 ms | 1.94× |
| 29 000 ms | 8 000 ms | 2 | 25 924 ms | 1.93× |

**关键发现**：实测会议语音的自然句间停顿约 1.55–1.64 秒。当阈值设为 1 500 ms 时几乎不触发合并，
优化完全失效；提高到 2 500 ms 后合并生效，**吞吐提升约 3.4 倍**。因此把默认值定为 2 500 ms，
并在代码注释中记录了该实测依据。

**索引对齐保证**：单元内文本按各语音段的时长权重切分回填（`SentenceSplitter::splitByWeights`），
且切分点优先落在句子边界，因此 `segments ↔ asr.segments ↔ speakerIds ↔ sentences` 始终一一对应
（由 `pipeline.转写单元分组与索引对齐` 用例守护）。

### 5.3 资源占用

| 指标 | 实测 | 目标（NFR-1） | 结论 |
| --- | --- | --- | --- |
| 进程常驻内存 | 27 MB（不含模型权重） | ≤ 1.5 GB | 满足 |
| whisper small 模型 | 487 MB（CPU） | — | — |
| 转写速度 | 2.18× 实时（small，8 线程） | ≥ 1.5× | 满足 |
| 转写速度 | 实测 `base` 模型更快（约 4–5× 实时） | ≥ 1.5× | 满足 |

## 9. 遗留风险与后续测试建议

| 项 | 说明 | 建议 |
| --- | --- | --- |
| 多说话人真实场景 | 本轮端到端素材为单一合成音色，无法验证 MFCC 声纹嵌入在真实多人会议中的分离质量 | 用真实多人会议录音建立评测集，统计 DER（说话人错误率） |
